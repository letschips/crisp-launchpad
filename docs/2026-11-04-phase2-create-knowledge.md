# 第二期（0.7.0）：创作页、知识页与计数口径

2026-11-04 作者批准。同时处理作者反馈：「新建行动」会先跳到 Tempo 再弹窗，和「打开 Tempo」没有区别。

## 范围

1. **新建行动原地弹窗**：Tempo 新增 `openQuickAddModal()`（0.14.0），在当前页面弹出同一个新建任务弹窗，不切换到 Tempo。Launchpad 优先调用它；旧版 Tempo 或未激活时退回 `quick-add-task` 命令（会打开 Tempo 并提示激活）。
2. **计数口径统一**（实测：今天一行 52、知识页 KPI 51、复盘 47）：
   - 「待整理」= 全库 `raw/inbox` 里 `routing_status` 未归位的材料，今天一行、知识页 KPI、知识页待整理卡片用同一个数。KPI 下面写各 Topic 的分布，不再只写主 Topic。
   - 复盘页和「待你判断」里的数来自 ANKS health 的 `STALE_INBOX`（vault_sweeper：未归位且超过 3 天），标签改成「超过 3 天未整理」，和「待整理」区分开。
   - 知识页其余 KPI（知识对象、原始素材、产出）也改为全库各 Topic 合计，副标题写分布。
3. **创作页**：
   - 「内容流向」分段条每段带阶段名和数量（图例），点图例跳到流水线里对应阶段。
   - 流水线每个项目显示「N 天未动」（取内容快照的 `updated_at`，没有时用文件修改时间）；发布前的阶段超过 14 天标警示色。
4. **知识页**：待整理卡片列全库（多 Topic 时每行标 Topic），头部写总数，超过 6 条可展开全部；「本周知识库活动」改名「近 7 天更新」（按文件修改时间算的就是近 7 天），「（无 type）」改「未标类型」。

## 不做

复盘页热力图、系统问题清单（第三期）；不新增设置。

## 回归用例

- 新建行动：Tempo 有 `openQuickAddModal` 时调用它且不执行命令；没有该接口或返回 false 时执行 `crisp-tempo:quick-add-task`。
- 两个 Topic 各有未归位材料时，今天一行、KPI、待整理卡片三处数字相同，KPI 副标题列出两个 Topic。
- 「待你判断」和复盘页不再用「收件箱待检查 / 收件箱积压」，改为「超过 3 天未整理」。
- 分段条每段有阶段名标签；项目行有「N 天未动」，发布前阶段 ≥14 天为警示。
- 活动卡片标题为「近 7 天更新」，不出现「（无 type）」。

## 验收

`npm run check`、`npm run test:e2e`；Tempo `npm run check`；真实 Obsidian 只做不打扰的检查（作者在用时不切标签页）；发布 Launchpad 0.7.0 与 Tempo 0.14.0。
